
SPRINTS 0 - 1 

Esta Sprint tem como objetivo preparar todo o ambiente que será utilizado durante o desenvolvimento do Projeto Integrador de construção de um Large Language Model (LLM). Ao final desta etapa, todos os estudantes deverão possuir o ambiente computacional configurado, o repositório do projeto criado e uma visão geral da arquitetura dos modelos de linguagem que será desenvolvida ao longo do semestre.

Esta Sprint não contempla implementações do modelo propriamente dito, sendo dedicada à organização da infraestrutura necessária para o desenvolvimento das próximas etapas.

Atividades


1. Criar o repositório do projeto

Cada dupla deverá criar um repositório (GitHub, GitLab ou plataforma equivalente) que será utilizado durante todo o semestre.

O repositório deverá armazenar todo o desenvolvimento do projeto, incluindo:

código-fonte;
notebooks;
glossário técnico;
documentação;
experimentos;
relatórios;
resultados obtidos em cada Sprint.
Recomenda-se a utilização de uma estrutura organizada em diretórios, permitindo acompanhar a evolução incremental do projeto.

2. Configurar o ambiente de desenvolvimento

Instalar e validar o ambiente que será utilizado durante todo o semestre.

Ao final desta etapa, todos os integrantes do grupo deverão conseguir executar programas em Python utilizando o PyTorch.

3. Leitura do Capítulo 1

Realizar a leitura integral do Capítulo 1 – Understanding Large Language Models.

Durante a leitura procure responder questões como:

O que caracteriza um Large Language Model?
Qual a diferença entre IA, Machine Learning e Deep Learning?
Como os modelos GPT estão organizados?
Quais são as principais etapas do treinamento de um LLM?
Qual é o fluxo geral de funcionamento de um modelo de linguagem?

O objetivo desta leitura é compreender a arquitetura geral que será construída durante o semestre.

4. Leitura do Apêndice sobre PyTorch

Realizar a leitura do apêndice do livro dedicado ao PyTorch.

Essa leitura tem como finalidade familiarizar os estudantes com a biblioteca que será utilizada nas implementações desenvolvidas ao longo do projeto.

Durante a leitura procure compreender:

criação de tensores;
operações básicas;
manipulação de dimensões;
operações matriciais;
funcionamento do autograd;
construção de modelos utilizando módulos do PyTorch.

Não é necessário memorizar todos os comandos apresentados. O objetivo é compreender a estrutura geral da biblioteca e adquirir familiaridade com sua documentação.

5. Construção do Glossário

Elaborar o glossário correspondente ao Capítulo 1.

Entregáveis

Ao término da Sprint 0, cada grupo deverá entregar:

Link do repositório do projeto, contendo:
 - Ambiente computacional configurado e funcional.
 - Arquivo README.md contendo a descrição do projeto.
 - Glossário do Capítulo 1.


SPRINT 2 

Nesta Sprint será iniciado o desenvolvimento efetivo dos componentes computacionais do modelo de linguagem.

A partir dos conceitos apresentados no Capítulo 1, o objetivo desta etapa é compreender como um texto é transformado em uma representação numérica que possa ser utilizada como entrada para uma rede neural.

Ao final da Sprint, o grupo deverá ser capaz de explicar e implementar as principais etapas do processamento inicial dos dados de um LLM, incluindo tokenização, construção do vocabulário, conversão para Token IDs, preparação de sequências de treinamento, embeddings, Positional Embeddings e carregamento dos dados para treinamento.

O projeto possui caráter incremental: os componentes desenvolvidos nesta Sprint deverão ser organizados de forma que possam ser posteriormente integrados ao modelo completo. 

1. Leitura orientada

Realize a leitura integral do Capítulo 2 – Working with Text Data, conforme a referência principal do projeto.

Durante a leitura, procure compreender:

como um texto é dividido em unidades menores;
o que é um token;
como os tokens são associados a identificadores numéricos;
como é construído um vocabulário;
como uma sequência de texto é transformada em uma sequência de números;
como são formados os pares de entrada e alvo utilizados no treinamento;
por que os tokens precisam ser convertidos em vetores;
o papel dos embeddings;
a necessidade de representar a posição dos tokens;
como os dados são organizados para serem fornecidos ao modelo.
A leitura deve priorizar a compreensão da relação entre as diferentes etapas do processamento, e não apenas a reprodução dos códigos apresentados no livro.

2. Glossário técnico

Atualize o Glossário Técnico do Projeto LLM com os conceitos introduzidos no Capítulo 2.

Para cada termo, apresentar:

termo original;
tradução ou equivalente técnico em português;
definição;
função no modelo de linguagem;
relação com outros conceitos;
exemplo conceitual ou computacional, quando pertinente.

   ↓

   ↓

3.1 Tokenização

Implemente o processo de tokenização utilizado no capítulo.

O código deverá permitir receber um trecho de texto e produzir uma representação baseada nos tokens identificados.

Teste o funcionamento utilizando diferentes frases e observe como a representação textual é modificada.

3.2 Vocabulário e Token IDs

Implemente a associação entre os tokens e seus respectivos identificadores numéricos.

O sistema deverá permitir:

construir ou utilizar um vocabulário;
converter tokens em Token IDs;
recuperar tokens a partir dos respectivos IDs;
tratar tokens especiais utilizados pelo processo.
O grupo deverá demonstrar que compreende a relação:

Token ↔ Token ID ↔ Vocabulário


3.3 Preparação das sequências

Implemente a preparação dos dados para treinamento do modelo.

A partir de uma sequência de tokens, construa as entradas e os respectivos alvos que posteriormente serão utilizados pelo modelo para realizar a previsão do próximo token.


3.4 Embeddings

Implemente a transformação dos Token IDs em representações vetoriais.

O grupo deverá observar a dimensão dos vetores produzidos e compreender que os tokens deixam de ser representados apenas como identificadores inteiros e passam a possuir uma representação vetorial que poderá ser processada pelas camadas seguintes da arquitetura.

3.5 Positional Embeddings

Implemente a incorporação da informação de posição dos tokens.

O grupo deverá demonstrar experimentalmente que a representação de um token deve considerar também sua posição dentro da sequência.

3.6 Organização dos dados

Implemente a estrutura necessária para organizar os dados em conjuntos que possam posteriormente ser utilizados durante o treinamento.

Utilize o mecanismo de carregamento de dados apresentado no capítulo, incluindo o DataLoader quando aplicável.

Ao final desta etapa, o grupo deverá possuir uma estrutura capaz de produzir lotes de dados de entrada e seus respectivos alvos.

4. Experimentação

A implementação deverá ser acompanhada de experimentos.

Os experimentos devem permitir observar o impacto de diferentes configurações sobre os dados e suas representações.

Sugere-se investigar, no mínimo:

diferentes tamanhos de contexto;
diferentes tamanhos de lote;
diferentes dimensões de embedding;
diferentes sequências de entrada;
quantidade de tokens produzidos para diferentes textos;
relação entre tamanho do contexto e quantidade de amostras;
dimensões das estruturas produzidas pelo pipeline.
Os experimentos devem permitir observar alterações no comportamento, desempenho ou custo computacional da solução.

5. Análise dos resultados

Após os experimentos, o grupo deverá elaborar uma análise técnica.

A análise deverá responder, pelo menos, às seguintes questões:

Por que um LLM não pode trabalhar diretamente com o texto bruto?
Qual é a função do vocabulário?
Qual é a diferença entre um token e um Token ID?
Por que os Token IDs não são utilizados diretamente como representação semântica?
Qual é a função dos embeddings?
Por que é necessário representar a posição dos tokens?
Qual é a relação entre tamanho do contexto e quantidade de amostras de treinamento?
Qual é o impacto da dimensão do embedding sobre as estruturas utilizadas pelo modelo?
Qual é a função do DataLoader no pipeline?
Quais informações produzidas nesta Sprint serão utilizadas pelo mecanismo de atenção da Sprint seguinte?

A análise deverá apresentar argumentos técnicos e, sempre que possível, utilizar resultados obtidos nos próprios experimentos.

O documento do projeto estabelece que a análise não deve se limitar à apresentação de código, gráficos ou valores numéricos, devendo relacionar os resultados aos conceitos estudados.

SPRINT 3 

Nesta Sprint será desenvolvido o mecanismo central utilizado pela arquitetura Transformer: o mecanismo de Attention. A partir dos dados preparados na Sprint 2, o grupo deverá compreender como o modelo pode estabelecer relações entre diferentes tokens de uma sequência e utilizar essas relações para construir representações contextuais. A Sprint será desenvolvida de forma incremental, iniciando com o conceito de atenção e avançando para Self-Attention, Scaled Dot-Product Attention, Causal Attention e Multi-Head Attention. Ao final da Sprint, o grupo deverá possuir uma implementação funcional do mecanismo de Multi-Head Attention, que será posteriormente integrado aos blocos Transformer da Sprint 4. Essa etapa é fundamental para a construção progressiva do modelo, pois os mecanismos de atenção serão utilizados posteriormente na arquitetura GPT.

SPRINT 4 

Nesta Sprint, os mecanismos de atenção desenvolvidos na Sprint 3 serão integrados aos demais componentes necessários para construir uma arquitetura GPT simplificada. O objetivo é compreender como os diferentes elementos do Transformer trabalham em conjunto e transformar as implementações anteriores em um modelo capaz de receber uma sequência de tokens e produzir previsões para o próximo token.

A primeira etapa será dedicada à construção do Transformer Block, explorando os conceitos de Layer Normalization, FeedForward Network e conexões residuais. Os estudantes deverão compreender a função de cada componente e sua contribuição para o funcionamento e a estabilidade da arquitetura. A partir desses elementos, será realizada a integração com o mecanismo de Multi-Head Attention desenvolvido na Sprint anterior.

Na segunda etapa, os componentes serão organizados em uma arquitetura GPT, com o empilhamento de múltiplos Transformer Blocks, normalização final e uma camada responsável por produzir os logits associados ao vocabulário. Serão realizados experimentos modificando parâmetros da arquitetura, como dimensão dos embeddings, número de heads, número de blocos e dimensão da rede FeedForward, observando seus efeitos no comportamento e no custo computacional do modelo.

Na etapa final, será implementado o processo de inferência e geração autoregressiva de texto. A partir de uma sequência inicial, o modelo deverá prever o próximo token e utilizá-lo como parte do contexto para realizar novas previsões. Também serão exploradas estratégias de seleção dos tokens e, quando pertinente, parâmetros como temperatura e top-k.

Entregável 1 – Glossário

Atualizar o glossário cumulativo do projeto com os principais conceitos estudados no Capítulo 4, mantendo o padrão adotado nas Sprints anteriores. Devem ser contemplados conceitos como Transformer, Transformer Block, LayerNorm, conexões residuais, FeedForward Network, GELU, Dropout, logits, Language Model Head, inferência e geração autoregressiva.

Para cada conceito, apresentar a definição, sua função no modelo GPT e sua relação com os demais componentes da arquitetura.

Entregável 2 – Implementação do Transformer Block

Implementar o Transformer Block a partir dos componentes desenvolvidos nas Sprints anteriores. A implementação deverá integrar Multi-Head Attention, LayerNorm, FeedForward Network e conexões residuais.

Você deverá documentar a estrutura utilizada e explicar a função de cada componente, incluindo as dimensões dos principais tensores envolvidos.

Entregável 3 – Construção do modelo GPT

Integrar os Transformer Blocks em uma arquitetura GPT simplificada. O modelo deverá utilizar os embeddings e mecanismos de atenção desenvolvidos anteriormente, permitindo o processamento de uma sequência de Token IDs e a produção de logits para o vocabulário.

Deverá ser possível identificar no código a organização dos principais componentes da arquitetura e compreender como eles participam do processamento da sequência.

Entregável 4 – Inferência e geração de texto

Implementar o processo de inferência e geração autoregressiva. A partir de uma sequência inicial, o modelo deverá realizar a previsão do próximo token e utilizar o token produzido para ampliar o contexto e continuar a geração.

Você deverá documentar o procedimento utilizado e explicar a relação entre logits, probabilidades, seleção do próximo token e geração autoregressiva.

Entregável 5 – Experimentação e análise

Realizar experimentos alterando parâmetros da arquitetura ou do processo de geração. Podem ser investigados, por exemplo, o número de Transformer Blocks, número de heads, dimensão dos embeddings, dimensão da FeedForward, dropout, tamanho do contexto e parâmetros de geração.

Para cada experimento, registrar a configuração utilizada, os resultados observados e uma análise que relacione as alterações realizadas ao comportamento do modelo e ao custo computacional.

SPRINT 5 

Entregável 1 – Glossário

Atualizar o glossário cumulativo com os conceitos relacionados ao treinamento e à avaliação de modelos de linguagem. Para cada termo, apresentar sua definição, função no treinamento e relação com os demais componentes do modelo.

Entregável 2 – Avaliação do modelo

Implementar a avaliação quantitativa do modelo GPT utilizando a perda (loss) calculada sobre os dados. Vocêe deverá compreender como a cross-entropy loss mede a diferença entre as previsões do modelo e os tokens esperados, além de calcular as perdas dos conjuntos de treinamento e validação.

Também deverá investigar a métrica perplexity e sua relação com a capacidade do modelo de prever os próximos tokens. Os resultados devem ser registrados e interpretados, considerando o estado inicial do modelo e sua evolução durante o treinamento.

Entregável 3 – Implementação do treinamento

Implementar a rotina de treinamento do GPT utilizando PyTorch. A implementação deverá contemplar a iteração por épocas e lotes, o cálculo da função de perda, a retropropagação dos gradientes e a atualização dos pesos do modelo por meio de um otimizador, conforme apresentado no capítulo.

Você deverá registrar os parâmetros utilizados, como número de épocas, tamanho dos lotes, taxa de aprendizado e configuração do otimizador. Também deverá acompanhar as perdas de treinamento e validação durante a execução, verificando se o modelo está efetivamente aprendendo a tarefa de previsão do próximo token.

Entregável 4 – Experimentos de treinamento

Realizar experimentos modificando parâmetros do treinamento e analisar seus efeitos sobre a convergência, a qualidade dos textos gerados e o custo computacional. Devem ser considerados, conforme os recursos disponíveis, diferentes números de épocas, taxas de aprendizado e configurações de treinamento.

A análise deverá comparar os resultados obtidos, identificar possíveis sinais de sobreajuste e discutir as diferenças entre o comportamento observado nos dados de treinamento e nos dados de validação.

Entregável 5 – Estratégias de geração de texto

Investigar estratégias de decodificação para controlar a seleção dos próximos tokens durante a geração. O trabalho deverá comparar a seleção do token com maior probabilidade (greedy decoding) com a amostragem probabilística e explorar os efeitos da temperatura e do top-k sampling.

Deve-se utilizar o mesmo contexto inicial para comparar as saídas produzidas, documentando as diferenças de diversidade, repetição e coerência. A análise deverá distinguir os efeitos das estratégias de geração daqueles decorrentes do treinamento dos pesos do modelo.

Entregável 6 – Salvamento e carregamento dos pesos

Implementar o salvamento e o carregamento dos pesos do modelo, permitindo preservar o estado obtido ao final do treinamento e retomar o trabalho posteriormente. O estudante deverá demonstrar que o modelo carregado consegue realizar inferência e gerar texto utilizando os parâmetros salvos.

O procedimento deverá ser documentado no repositório, incluindo as informações necessárias para identificar a configuração do modelo e reproduzir os experimentos.

Entregável 7 – Documentação técnica

Consolidar no repositório os códigos de treinamento e avaliação, os experimentos realizados, os registros das perdas, as amostras de texto geradas e as conclusões obtidas. O relatório deverá explicar as configurações utilizadas, apresentar os resultados quantitativos e qualitativos e discutir as limitações do treinamento realizado.

A documentação deve permitir compreender o processo de treinamento e reproduzir os principais experimentos.
